## Decisions

All made on 2026-11-21 while creating the spec, under J's authorization to decide without asking.
"PRD" = `enterprise-agent-factory-service-cli-PRD.md` in this directory.

| Id | Decision | Why |
|---|---|---|
| D-C1 | **Snapshot pinning.** `api/openapi.yaml` is a verbatim copy of `-restapi/api/openapi.yaml`. `api/SOURCE` records `repo`, `ref`, `commit`, `sha256`, `synced_at`. `make contract-check` recomputes the sha256 and fails on mismatch (part of `make gate` and CI). `make contract-sync RESTAPI_REF=<ref>` (or `RESTAPI_DIR=<path>` for a local clone) copies the file, rewrites `SOURCE`, and runs `make generate`. The snapshot is never edited here. It is pinned first to `feat/restapi-feature-complete` (commit `081de14` at spec time), re-synced at the start of every milestone (task `Mn-0`), and re-pinned to the `-restapi` release tag once `-restapi` merges to `main` (task M6-X2) | PRD §6 ("at a release tag"), contract §8 (regenerate in its own PR), ADR-002; `-restapi` has no tag yet |
| D-C2 | **Own generator for descriptors.** `tools/afsgen` reads the snapshot with `gopkg.in/yaml.v3` and writes `internal/spec/operations_gen.go` (data-dictionary §1). `make generate-check` regenerates into a temp dir and diffs; CI fails on drift | The `x-afs-*` extensions carry the CLI facts; a dedicated generator keeps them first-class and the runtime dependency-free |
| D-C3 | **oapi-codegen v2.8.2 for types only**, run as `go run github.com/oapi-codegen/oapi-codegen/v2/cmd/oapi-codegen@$(OAPI_CODEGEN_VERSION)` from the Makefile (the same pattern as golangci-lint), output `internal/client/gen/types.gen.go`. The PRD says "pinned in `tools.go`/`go.mod`"; the Makefile pin is used instead so tool dependencies stay out of `go.mod` and `govulncheck`'s scope. Fallback if a future snapshot breaks it: `afsgen` emits the request types the overrides use | Spiked green on the 3.1 snapshot (research RQ-1) |
| D-C4 | **Generic executor + per-operation overrides.** Every one of the 180 operations is callable from M0 through the generic executor. A command is *done* at its milestone when its override has ≥ 1 example, its table columns, golden `table`/`text`/`help` files and any special handling. `internal/cli/milestones.go` (written once in M0-K5 from tasks.md Appendix A) maps each operation to its milestone; `CurrentMilestone` is bumped only by milestone exit tasks; a test requires every operation at or below it to be done | Keeps 180 commands uniform, makes CLI-US-7 green from M0, and lets streams work in parallel on disjoint files |
| D-C5 | **`--output json` prints the raw body re-indented** (`json.Indent`), so field names, nesting, order, `null`s and unknown fields of a newer minor survive. With `--query`, the body is decoded (`UseNumber`), queried, and re-encoded with sorted keys. `yaml`, `table` and `text` decode into an ordered tree | CLI-6 "exactly the API's fields"; typed decoding loses `null`s and unknown fields (RQ-2) |
| D-C6 | **`--cli-input-json`** is one object holding parameters and body members (AWS style). Keys equal to a path, query or header parameter name are taken as parameters; `version` becomes `If-Match`; the remaining members are the body, sent with their order and values unchanged. Explicit options override input keys. Accepts inline JSON or `file://` (except the secret operations, CLI-9). `--generate-cli-skeleton` prints every parameter and writable body member (required first, then optional, each with an empty value of its type) and makes no call | CLI-2, CLI-US-2 |
| D-C7 | **Pagination token.** The CLI's `NextToken` is `base64url({"t": server token, "s": items to skip})`. `--max-items` with `--output csv` is a usage error (252); `--no-paginate` with csv prints the page and writes `NextToken: <X-Afs-Next-Token>` to stderr | CLI-7, CLI-6; CSV pages cannot be cut mid-page without re-parsing |
| D-C8 | **Safe updates** use a reader table (data-dictionary §3) covering all 59 `If-Match` operations, checked against the snapshot by a test. Operations whose resource has no `version` (`PutTeamModels`) send no `If-Match` (CD-2 allows it on `PUT`) and print no notice. The notice `Applied to version N; …` is printed after a successful write. On `412` the CLI prints the current version from the response `ETag` when present (CLI-CD-3), else from one more read; if that read fails, the message omits the version | CLI-10, CLI-US-6; `412` carries no version today (RQ-6) |
| D-C9 | **`--wait`** uses a wait table (data-dictionary §4). Done = `status.phase == Ready` and `observedGeneration ≥` the mutation response's `generation`, so a stale `Ready` does not end the wait; `Failed`/`Degraded` → 254 with conditions on stderr. Interval 5 s or `Retry-After`. `--wait-timeout` takes a Go duration (`90s`, `10m`; default `10m`). After `Ready` the CLI prints the resource from its `Get` | CLI-12, CLI-US-2 ("printing the final team") |
| D-C10 | **Profile `team_id`** fills only a *path* `teamId` that the user omitted. It never fills an optional query filter (for example `work-orders list-work-orders --team-id`), which would silently narrow results | CLI-3 |
| D-C11 | **`endpoint_url`** is the host root (`https://afs.example.com`); the CLI appends the snapshot's paths, which already start with `/v1` | Snapshot paths (research) |
| D-C12 | **No `GetMe` cache in v1.** `AccessDenied` already carries `details.requiredPermission`, which the error message prints; `sso get-caller-identity` is the only `GetMe` call | One operation, one call; AGENTS.md says the CLI *may* cache it |
| D-C13 | **Contract version** comes from the snapshot's `info.version` (`1.1.0` today; root document v1.2.0, CLI-CD-2). `afs --version` prints `afs-cli/<version> contract/<major.minor> <go version> <os>/<arch>`. One stderr notice per process when `X-Afs-Contract-Version`'s minor is newer than the CLI's, or its major differs | CLI-15, NFR compatibility, D47 |
| D-C14 | **Releases** with GoReleaser v2 (OSS): archives for darwin/arm64, darwin/amd64, linux/arm64, linux/amd64, windows/amd64; `checksums.txt` signed keyless with cosign from the release workflow's OIDC identity; macOS notarized with quill; Windows Authenticode through `osslsigncode`; Homebrew formula pushed to the tap. CI runs `goreleaser check` and a `--snapshot` build on every PR; signing jobs run only when the secrets exist (OQ-S1) | CLI-15, research RQ-14 |
| D-C15 | **Config files are AWS-style INI**: `~/.afs/config` with `[default]` and `[profile <name>]`, `~/.afs/credentials` with `[<name>]` and `api_key`. `AFS_CONFIG_FILE` and `AFS_SHARED_CREDENTIALS_FILE` override the paths (tests, CI) | AWS CLI parity (AGENTS.md) |
| D-C16 | **Secret input** is sent byte for byte (no newline trimming, as the AWS CLI does for `file://`); `file://` and `fileb://` both must decode as UTF-8 (the API value is a JSON string) and be 1–65536 bytes, else 252. The prompt reads without echo from the terminal; with no terminal and no `--secret-value`, exit 252 | CLI-9, `SecretValue` schema |
| D-C17 | **`UpdateWorkOrderRepo` without `--if-match`** reads with `ListWorkOrderRepos` (matching `host` and `repo`; there is no single-repository `GET`). A workload principal cannot make that read today (`work-orders:read` missing), so the CLI prints the API's `AccessDenied` followed by `Pass --if-match <version> (the version printed by the previous update-repo).` and exits 254. With `--if-match`, workers succeed. CLI-US-10's first criterion is tested against a fake that grants the read (the contract change requested in CLI-CD-1) and against one that denies it | RQ-13, OQ-S2 |
| D-C18 | **`CreateImport`** sends `{bundle: <bundle file>, accountMap: <map file>}` as the body and `?dryRun=true` unless `--no-dry-run`. The PRD's "the bundle file is the request body" is read as the `bundle` member, as `ImportRequest` requires. The 100 MB limit is checked on the bundle file size before any read of its content | RQ-9; OpenAPI wins |
| D-C19 | **Ephemeral `create-team`** sends `budget: {period: "lifetime", amountUsd, thresholds?}`. `TeamBudgetInput` has no `onExhaust`; an ephemeral team's budget always blocks (contract §4.9: `notify` is for persistent teams), so the PRD's "`onExhaust: block`" is implied, not sent (CLI-CD-5) | OpenAPI wins |
| D-C20 | **`test-notification-channel`**: `200` with `delivered: true` → print, exit 0; `200` with `delivered: false` → print the result to stdout, then `An error occurred (DeliveryFailed) when calling the TestNotificationChannel operation: <error>` and `Request ID:` on stderr, exit 254 (`DeliveryFailed` is a CLI-side code, documented in user-docs); `202` `pending: true` → print, stderr `The test is still running; run afs teams describe-notification-channel to see the result.`, exit 0 | CLI-US-19, CD-3 |
| D-C21 | **Timeouts**: `--cli-connect-timeout` is the dial plus TLS handshake timeout; `--cli-read-timeout` bounds the wait for response headers and each body read (reset per read). `0` disables either | NFR reliability |
| D-C22 | **Pager**: only when stdout is a terminal and `--no-cli-pager` is absent; command from `AFS_PAGER`, else `PAGER`, else `less -R`; an empty `AFS_PAGER` disables it | AWS CLI v2 parity |
| D-C23 | **Argument parser**: hand-written, no cobra/pflag. AWS semantics: global options anywhere; `--opt value` and `--opt=value`; list options take values up to the next `--`; unknown option → 252 with the operation's usage | Command table is generated; flags are data, not code; keeps startup < 100 ms |
| D-C24 | **Retries** (CLI-11): at most 3 attempts; delay `rand(0, 200 ms × 2^(n-1))` (full jitter), or `Retry-After` when longer. "Connection dropped after the request was sent" is detected with `httptrace.WroteRequest`; such a failure is retried only for `GET` or a request with `Idempotency-Key`. Clock, sleeper and random source are injected | CLI-11, §5.1 retries criteria |
| D-C25 | **`secretKey`** (`create-api-key`, `admin create-api-key`): printed in the normal output once (json includes it; table has a `SecretKey` column), with `Store this key now; it cannot be shown again.` on stderr. A replay (`Idempotent-Replayed: true`, no `secretKey`) prints the metadata and `This is a replay; the key's secret was shown only to the first request. Delete the key and create another if it was lost.` on stderr | NFR security, D52 |
| D-C26 | **Deletes**: `202` responses (CD-1) print the returned body; `204` prints nothing | CD-1 |
| D-C27 | **Completion** scripts for bash, zsh, fish and PowerShell are rendered from the registry by templates in `internal/cli/completion` (services, operations, options, enum values) | CLI-3, OQ-C5 |
| D-C28 | **Spec files, `Makefile`, CI workflows** are owned by the orchestrator and the `-K`/`-X` tasks. A stream may add to `go.mod` only modules from spec.md §7.3 (a module enters `go.mod` with its first use, because `go mod tidy` must leave `go.mod` unchanged); the orchestrator resolves `go.mod`/`go.sum` merge conflicts by taking the union and running `go mod tidy`. A module not in §7.3 needs an orchestrator decision recorded here | Parallel streams must not collide |
| D-C31 | **`pools describe-pool --output table`** shows the `Pool` fields (`workers` = desired workers, state, phase). `GetPool` does not return reporting, working, idle or impaired counts; those are in `GetPoolStatus`, so `pools get-pool-status --output table` shows all five. CLI-US-8's "describe-pool shows desired, reporting, working, idle and impaired" is met by `get-pool-status` (one operation, one call); CLI-CD-6 asks for the counts on `Pool` | OpenAPI `Pool.workers` is an integer; `PoolStatus.workers` has the five counts |
| D-C32 | **Registry merges registrations per operation**: several files may each register a part for one `operationId` (examples appended, extra options appended, validators and builders chained in registration order). Two registrations that both set `Columns`, `Rename` of the same parameter, or `After` are a startup error caught by a test | Lets M5-B extend `create-team` (owned by M1-A's file) from its own file |
| D-C33 | **Endpoint scheme**: `https://` required; `http://` accepted only for loopback hosts (`localhost`, `127.0.0.0/8`, `::1`) so tests and local port-forwards work; any other `http://` endpoint → exit 255 `endpoint_url must use https`. Proxies from `HTTPS_PROXY`/`NO_PROXY` (Go default) | Bearer tokens and API keys must not cross the network in clear text |
| D-C34 | **No `--ca-bundle` in v1** (not in the PRD). Go's system roots honour `SSL_CERT_FILE` and `SSL_CERT_DIR` on Linux and macOS; documented in `user-docs/troubleshooting.md` | Smallest surface that still works behind an enterprise TLS proxy |
| D-C35 | **Invalid configuration values**: an invalid `--output`, `--color` or numeric option on the command line → 252; the same invalid value from the environment or a profile → 255 (configuration error) naming its source; an unknown `--profile`/`AFS_PROFILE` → 255 `The config profile (<name>) could not be found` | AWS CLI parity; exit-code meaning of data-dictionary §7 |
| D-C29 | **Workload token** credential (`AFS_API_TOKEN_FILE`, default `/var/run/secrets/afs/api/token` when present, re-read per request) is built in M6-B as PRD §7 schedules it; M0-C2 reserves its slot at the end of the chain | PRD §7 M6 |
| D-C30 | **Command reference** in `user-docs/reference/` is generated by `tools/docgen` from the registry and help text at each milestone exit, not hand-written by streams | Avoids collisions; help and docs cannot drift |

## Edge cases and solutions

| Case | Handling |
|---|---|
| `--output csv` on a non-*CSV* operation, or with `--query` | 252 before any call |
| `--page-size` outside 1–100 | 252 |
| Path segment values with `/` (`--repo host/owner/repo`) | split into the three path parameters; each segment escaped with `url.PathEscape` |
| `PUT` that creates (read returns `404`) | no `If-Match`, no notice |
| Read for a list-based `Reader` paginates | the read follows `nextToken` until the item is found; not found → treated as `404` |
| `--wait` on a mutation whose response has no `generation` | phase check only |
| Ctrl-C during a retry back-off or a `--wait` sleep | the sleep is cancelled; exit 130; under `--wait` stderr says the mutation stands |
| `AFS_API_KEY` set together with `--profile` that has an SSO token | the key wins; `--debug` logs `credential source: env AFS_API_KEY` |
| Credentials or cache file wider than 0600 | exit 255, `chmod 600 <path>`, no call (Windows: mode checks skipped, documented) |
| Server sends an unknown error `code` | rendered as given, exit 254 |
| Response without `X-Request-Id` | `Request ID:` line omitted |
| Kubeconfig run twice | entries replaced by name, one context remains |
| `--kubeconfig -` | API YAML unchanged to stdout; no merge, no mode logic |
| Empty list response | `json`/`yaml` print `{"items": []}` as returned; `table` prints the header row only; `text` prints nothing; exit 0 |
| Very long auto-paginated listings | JSON pages are merged in memory (bounded by what the API serves; `--max-items` or `--no-paginate` for large sets); CSV pages are streamed page by page to stdout, never buffered whole |
| An operation added or removed by a re-sync | CLI-US-7 test fails until `milestones.go`/Appendix A and the overrides follow (M1-0..M6-0) |
| Server returns a body whose media type is not the one requested (for example JSON error on a CSV request) | error envelope parsed as JSON whatever was requested; a 2xx in the wrong type → exit 255 `unexpected response media type` |

## Deviations from plan

Recorded during M0 (2026-11-21):

- **Descriptors carry no examples.** `operations_gen.go` omits `Example` and `RequestExample`; the replay test reads examples from the embedded snapshot. Keeps startup under 100 ms (measured about 2 ms to first request).
- **`DeriveOptions` lives in `internal/cli`** (not `exec/options.go`): the registry needs it at `Finalize`, and `exec` imports `cli`.
- **Hand-rolled device grant** in `internal/sso` instead of `golang.org/x/oauth2`, so the clock and sleeper are injectable and no dependency is added.
- **`internal/secretinput` created in M0** (minimal: `file://`, `fileb://`, `-`, never a plain argument) because `exec.Build` needs it; M2-B1 extends it with the no-echo prompt.
- **Coverage** is computed with `-coverpkg=./internal/...` over the whole tree (so the replay and integration tests count for the packages they exercise); generated code and the `internal/golden` test helper are excluded. 90.8% at M0 exit.
- **`sso login`** writes the resolved `sso_provider_id`, `sso_issuer` and `sso_client_id` into the profile when they are missing.
- **Safe-update readers are derived, not tabulated.** `safeupdate.ReaderFor` finds a same-path `GET` (after dropping a trailing literal such as `/value` or `/state`) or the parent collection's list and matches the item by `id`, `name`, `key` or the path parameter name. Only `PutSetting` and `UpdateWorkOrderRepo` have no reader and send no `If-Match` unless `--if-match` is given (D-C17 read of `ListWorkOrderRepos` is still to do in M5/M6 with the composite `host/owner/repo` match). The "Applied to version N" notice of D-C8 is replaced by a stderr line before the write: `Read the current version N; sending If-Match: "N"`.
- **`--wait` interval** is 5 s (client retry `Retry-After` is honoured by the client); the poll uses the generation of the mutation response.
- **Pagination token** `{"t","s"}` is implemented as D-C7 says; `s` is used when a server returns more items than `maxResults`.
- **Debug redaction** masks `secretKey` in response bodies; `exec` prints it once from the raw body (D-C25 is for M4).
- **`afs help <service> [<operation>]`** is accepted as well as `afs <service> <operation> help` and `--help`.

Recorded during M1 (2026-11-22):

- **M1-0 / M2-0 / M3-0 re-sync: no change.** `-restapi` `feat/restapi-feature-complete` at `bfe8b05` still serves `api/openapi.yaml` with sha256 `3456b9e9...`, the pinned snapshot; nothing regenerated.
- **Shared test harness `internal/clitest`** (not in the plan): runs afs against an httptest server, replays the snapshot's documented response example, and `CheckOperations` proves "command done" per operation (example parses, columns, golden `table`/`text`/`help`, `AccessDenied` 254). Excluded from the coverage figure like `internal/golden`. Goldens live in `testdata/<group>/<OperationId>.{table,text,help}.golden` of each service package; `services.TestDoneOperationsHaveGoldens` fails when an operation at or below `CurrentMilestone` has none.
- **`Pending()` no longer asks for columns on 204-only operations** (nothing to render); `TestPendingListsOperationsWithoutExamples` now derives its expectation from `CurrentMilestone`.
- **Bug fixed in `DeriveOptions`:** any `writeOnly` body field was turned into `--secret-value`. Only the `SecretValue` schema is a secret; `UpdateTeam.ceilingOverrideReason` (writeOnly, audit-only) is an ordinary `--ceiling-override-reason` option.
- **`PutTeamModels` reads nothing first** (`safeupdate.versionless`): its same-path `GET` is the model list, which has no version; D-C8 says no `If-Match`.
- **Enumerations are enforced client-side**, so examples use the API's values: roles `team_admin`/`team_viewer`, identity provider kinds `okta`/`entra_id`, setting keys from the `PutSetting` enum (for example `api.cors_origins`).
- **Table width:** at 80 columns the widest column shrinks first, so a ULID `Id` can show truncated with a `…` in `table`; `json`, `text` and `csv` are untouched.

Recorded during M2 (2026-11-22):

- **`internal/secretinput` prompt** (M2-B1): `Reader.Prompt` with an injectable `ReadPassword`; `ErrNoValue` when there is no terminal. `cli.Env.ReadPassword` is set by `NewEnv` with `golang.org/x/term` v0.47.0 (spec 7.3) only when stdin is a terminal; the exec `Build` prompts for a missing *required* sensitive body field, so `--secret-value` can be left out on a terminal. Prompt text goes to stderr, the typed value is never echoed.
- **`NewEnv` now detects terminals** (`StdinTTY`, `StdoutTTY`). M0 never set them in the real binary, so the pager and colour auto-detection were inert outside tests.
- **412 message (CLI-US-6.1, D-C8):** `exec.currentVersionOn412` takes the version from the response `ETag`, else one more read; `ReportError` prints `The resource changed (version N). Re-run with --if-match N to apply your change to the latest version.` A 428 prints a hint to pass `--if-match`.
- **Error details:** `ReportError` prints `Dependents: a, b` (`details.dependents`) and `Missing tags: ...` (`details.missingTags`).
- **CLI-US-12.4** (same name in two teams) needs no override: agents are addressed by `--agent-id`; the test proves both creates and an id-addressed describe.
- **Help for sensitive options** now also says that leaving the option out prompts on a terminal.
- `Secret` columns show names and metadata only (never `secretsManagerArn`).

Recorded during M3 (2026-11-22):

- **Contract re-sync M1-0..M3-0: no change.** `-restapi` `feat/restapi-feature-complete` advanced from `bfe8b05` to `e5f1c5c` during the run; `api/openapi.yaml` at both is byte-identical to the pinned snapshot (sha256 `3456b9e9...`).
- **`Override.Dynamic`**: report and usage rows are shaped by `--group-by`, so their table columns follow the response (generic columns). `Pending()` and `clitest` accept `Dynamic` in place of a column list. The generic column picker spreads a usage row's `key` object into `key.<member>` columns.
- **Report flags** (`reports/flags.go`): `--tag key=value` (list option, each pair sent as `tag.<key>=<value>`, CLI-CD-4), `--range` with `--from`/`--to` is 252, `--group-by` is checked against the contract's pattern client-side (252), `--tag` without `=` is 252.
- **`test-notification-channel`** follows D-C20 through an `After` hook; the `DeliveryFailed` code is CLI-side.
- Notification channel path parameter `id` is `--channel-id`.

Recorded during M4 (2026-11-22):

- **M4-0 re-sync: no change.** `-restapi` `feat/restapi-feature-complete` at `1bfb195` still serves the pinned snapshot (sha256 `3456b9e9...`).
- **Table never truncates identifiers** (user request): columns whose path leaf is `id` or ends in `Id`, `ID`, `Url` or `URL` keep their full width. Other columns shrink first (to a minimum of 6); when only identifier columns are left the line overflows 80 columns rather than cut an id. The vertical (single object) table keeps those values whole too. Goldens regenerated (supersedes the M1 note on `…`).
- **`TagPairs` option kind and `Override.Kinds`**: `--tags k=v k2=v2` (also JSON or `file://`) sends `[{"key","value"}]`, which is what `TagValue` is. This also fixes `create-team --tags`, whose M1 example (`--tags '{"project":"checkout"}'`) sent an object the API would refuse; the example now reads `--tags project=checkout cost-center=CC-1001`.
- **`Override.ResultKey`**: names the response member the table lists (`tags` for `get-team-tags`/`put-team-tags`), when it is not `items` or `rows`.
- **`Override.Precheck`**: runs in `exec.Build` before any option value or file is read; `create-import` uses it for the 100 MB bundle limit (`os.Stat`, no read).
- **`--revision-id`** replaces `--rev` on `describe-revision` and `restore-revision` (task M4-C3 names `--revision-id`; one name for one path parameter).
- **Log destinations** use `--destination-id`; service notification channels use `--channel-id` (as the team ones, D-C32 rename).
- **Report schedules**: `--range`, `--from`, `--to`, `--group-by`, `--tag key=value` build the stored `query` (`filters` `tag.<key>`); `--query-json` is the whole object and the flags are folded over it. CLI-CD-10 stays as decided: the body member is `--query-json`, not renamed, because `--query` is the global JMESPath option.
- **API keys** (`api-keys` and, in M6, `admin create-api-key`) share `ShowSecretNotice`: the secret is in the normal output once, `Store this key now; it cannot be shown again.` on stderr; a replay prints `This is a replay; ...`. `--debug` redacts the key (test).
- **`afs completion`** is a local command; scripts are generated from the command table (`internal/cli/completion`): services, operations, options and enumerated values. Goldens use a three-operation fixture (readable); `TestCompletionListsEveryCommand` covers the real table; `bash -n`, `zsh -n` and `fish --no-execute` run when the shell is installed; a bash behaviour test drives `_afs`.
- **Release pipeline (M4-G)**: `.goreleaser.yaml` (five targets, ldflags from `buildinfo`, `checksums.txt`, cosign `sign-blob` keyless, Homebrew formula skipped without `HOMEBREW_TAP_TOKEN`), CI job `goreleaser` (check and `--snapshot --skip=sign,publish,notarize`, then `--version` grep), `.github/workflows/release.yml` (gate, GoReleaser, verify job with `cosign verify-blob`; the macOS notarization and Windows signing jobs are gated on repository variables and are scaffolds until the certificates exist). `internal/release` tests read `.goreleaser.yaml` (targets, checksum, cosign) and build a binary with its ldflags to check `--version`. GoReleaser and cosign are not installed in the build environment, so the workflow files are unexercised.
- **Not done in M4 (needs J):** Apple notarization credentials, a Windows code-signing certificate, the `homebrew-tap` repository and `HOMEBREW_TAP_TOKEN`, a first `v0.1.0` tag (M4-X1: documented as pending).

## Contract deltas found in M0

| Id | Delta | CLI behaviour |
|---|---|---|
| CLI-CD-7 | `GetTeamReport` and `GetAgentReport` declare a query parameter that repeats a path parameter (`teamId`, `agentId`) | `afsgen` drops the duplicate query parameter |
| CLI-CD-8 | `ApiKey` has no `version`, yet `DeleteApiKey` and `DeleteServiceApiKey` require `If-Match` | The CLI sends no `If-Match` unless `--if-match` is given |
| CLI-CD-9 | `ErrorCode` has no idempotency codes; `idempotency_in_progress` and `idempotency_mismatch` are `details.reason` values of `Conflict` | Retry logic keys on `details.reason` |
| CLI-CD-10 | `CreateReportSchedule` and `UpdateReportSchedule` have a body member named `query`, which collides with the global `--query` | The option is `--query-json` until M4-D renames it |

M0 needs nothing else from `-restapi` or the root.
